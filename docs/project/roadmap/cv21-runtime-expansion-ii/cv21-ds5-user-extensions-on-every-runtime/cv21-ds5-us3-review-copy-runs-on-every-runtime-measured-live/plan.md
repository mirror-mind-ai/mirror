# Plan — CV21.DS5.US3

## Objective

Reviewed 2026-10-20 through four lenses — quality assurance, AI engineering, security,
operations — and ten amendments folded in at the Navigator's direction, listed under
*Review amendments* below. Approved the same day.

Prove, live and from the shipped package, that a user's extensions reach every plugin
runtime through the per-home plugin US2 built: `review-copy` with its real body —
listed, invoked in each runtime's spelling, running its `mirror consult` calls and
writing its report — and `hello`, the authoring guide's `command-skill`, reaching
`mirror ext hello ping` from a skill the runtime loaded. One scratch prefix, one scratch
Mirror home, four runtimes, each wired by nothing but the steps `mirror init` and
`mirror extensions install` print. The route is committed and re-runs; its evidence
carries version, binary, and date; and it is the isolated smoke CV21's Done Condition
asks for on Codex, Antigravity, and Grok, so each session must also be logged under the
runtime's `interface`.

## Scope

**The route**, `route.sh` in this story package, derived from TS1's (the scratch
directory, `keep`/`row`/`result`, the version stamp every step re-reads, the login
mechanics, `turn.js`, the baseline beside the scratch directory, `clean`, `untouched`):

1. `setup [registry|checkout]` — `npm pack mirror-mind@0.36.0` **from the registry**
   (the shipped package, not the checkout; TS1 packed the checkout), its tarball
   checked against the published `dist.integrity` before anything is installed, into a
   prefix whose path holds a space; a scratch Mirror home at `$D/mirror-minds/us3user`;
   the real-config baseline beside the scratch directory. `setup checkout` packs the
   checkout for a re-run on a fix not yet released; either way the mode and the
   installed version are stamped, and `probe` refuses to continue when the installed
   package is not the stamped one.
2. `probe` — the four binaries with version, path, and date; the readers per runtime
   TS1 established (Grok `inspect --json`, Codex `debug prompt-input`, Claude Code
   `plugin list`, agy `plugin list --json`); the session-logging reader per runtime
   (the `conversations.interface` the hooks write: `claude_code`, `codex`,
   `antigravity`, `grok_build`).
3. `install` — into the scratch Mirror home, with the scratch prefix's `mirror`:
   `review-copy` from `examples/extensions` with its real body, and `hello` from
   `fixtures/hello/`; the per-home plugin regenerated by the second install, its
   printed steps kept as the record of what US2 tells a user.
4. `wire <runtime>` — the canonical plugin through the steps `mirror init` prints for
   that runtime (so the hooks log the session), then the extensions plugin through the
   step US2's install printed. Nothing else. The negative read first: each reader
   says "not listed" before the step, and lists `ext-review-copy` and `ext-hello`
   after. Idempotent: a second `wire` finds both listed and stops.
5. `live <runtime> review-copy` and `live <runtime> hello` — one headless session
   each. **The prompt is the literal invocation** in the runtime's own spelling from
   TS1's decision (`ext-review-copy` on Claude Code and Grok,
   `$mirror-ext-us3user:ext-review-copy` on Codex, `/mirror-ext-us3user:ext-review-copy`
   on agy; `ext-hello` likewise), followed by the skill's own arguments — the fixture
   copy file and `gemini lite`, or `ping` with the canary — and the report path inside
   the scratch directory; nothing a model could satisfy without the skill, since a
   capable model can write an HTML review on its own. **One canary per cell**, carrying
   the runtime's name, so a ping from one runtime's session can never satisfy
   another's read. Every cell runs with `MIRROR_HOME` and `MIRROR_USER` set to the
   scratch home — unlike TS1's cells, which unset them, because here the hooks and
   `mirror consult` must reach the scratch home and nothing else — and with
   `OPENROUTER_API_KEY` passed in from the Navigator's configuration, never written
   to a file. Tool execution permitted the way each runtime's headless mode permits
   it, bounded: Claude Code `--allowedTools` scoped to `Skill`, `Read`, `Write`, and
   `Bash(mirror *)` if its pattern syntax allows, never `--dangerously-skip-permissions`
   (this cell runs on the real `HOME`); Codex `exec --dangerously-bypass-approvals-and-sandbox`
   (its default sandbox blocks the network `consult` needs) inside its scratch `HOME`;
   Grok `--yolo -m grok-4.7 --max-turns 6`; agy `--print --dangerously-skip-permissions`
   with a print timeout — 1.4.2 has the flag and expands skills in print mode by
   default; TS1's "denied a command" was without it. If agy still denies, the cell is
   one TUI session the Navigator drives and the route reads the scratch home afterwards
   (`live agy … tui`). The model id per session is recorded from the transcript. One
   retry per miss with the same prompt; both readings are kept — a pass on retry is a
   reliability finding, not a pass. The next Grok turn is refused past US$ 1.00 and the
   next `consult`-bearing turn past US$ 0.50 on the scratch ledger, both read, not
   estimated.
6. `verify <runtime>` — reads, not claims, each as a **before/after count** taken by
   `live` before the session and by `verify` after it, so the delta is that session's
   and a retry cannot double-count: the scratch ledger's `llm_calls` rows (count, model
   id, cost sum) for the `consult` calls; the report file at the named path, which
   must contain the model id the ledger recorded, or it is a report the model wrote on
   its own; `ext_hello_pings` for this cell's canary; `conversations` rows carrying the
   runtime's `interface`, read against what DS7 and DS10 measured — Claude Code, Codex,
   and Grok close at session end, Antigravity closes at the next session start, so the
   agy read expects one open conversation per session until a later start; the turn's
   tool calls classified by `turn.js`. A miss is diagnosed into one of three kinds and
   recorded as such: the skill never loaded (the plugin's), the skill loaded and the
   model did the work itself (the model's), or the command ran and failed (the
   sandbox's, the key's, or the network's). `verify` prints the two spend sums.
7. `clean` and `untouched` — as TS1's, with the keychain entry named and the baseline
   kept beside the scratch directory, and two more reads in `untouched`: the real
   homes' `conversations` counts, asserted unmoved since the baseline (a cell with the
   env unset would log into the real home silently — the failure TS1's unset-everything
   design existed to prevent); and new files in the real `~/Downloads` matching
   `*_AI_Reviews_*.html` created during the route's window, **named, never deleted** —
   the skill's default path, which the prompt overrides and a model may still follow.
   agy's credential is removed from 1.4.2's location (`antigravity-cli/antigravity-oauth-token`),
   CR144's finding. No evidence file may contain the key's value: the redaction check
   TS1's route applies to home paths applies to it.

**The fixture**, `fixtures/hello/`: `skill.yaml`, `migrations/001_init.sql`,
`commands/ping.mjs`, `commands/list.mjs`, `SKILL.md`, written from the authoring
guide's listings and nothing else — so the install is also the guide's first live
run through the shipped package.

**The evidence**, committed: `evidence/versions.tsv` (runtime, version, binary, date,
model, cost) and `evidence/table.tsv` (runtime × cell × result), plus two committed
transcripts for `turn.js` — one find, one search — that `static` classifies, so a
regression in the classifier is visible before a live run spends money. Raw outputs
stay under the scratch directory.

**Review amendments** (2026-10-20): A1 before/after counts and a canary per cell;
A2 the `interface` expectation per runtime from DS7/DS10; A3 the report pinned to the
ledger's model id; A4 `static` classifies two committed transcripts; A5 prompts as the
literal invocation, misses diagnosed into three kinds; A6 turn caps, Grok pinned, model
ids recorded, retries kept as reliability data; A7 the Claude cell's tools scoped and
`~/Downloads` named never deleted; A8 the key in no file and no evidence, the tarball's
integrity checked; A9 `setup` modes stamped and enforced, `wire`/`live` idempotent,
spend read and enforced, the real homes' conversation counts asserted; A10 agy headless
with `--dangerously-skip-permissions` first, TUI only if it still denies.

**The records**: `index.md`, this plan, `test-guide.md` with the measurements, and the
DS5 index row for US3.

## Non-Goals

- Do not implement sibling roadmap item: How extensions reach each runtime is written
  where a user reads it (TS4). This story records the measurements; TS4 writes them
  where a user reads them.
- Do not fix a runtime. Where a runtime cannot do a step — headless agy denying
  commands, a sandbox blocking the network — the record names it and the TUI or the
  flag stands in; the ceiling is a finding, as DS10 recorded Grok's.
- Do not touch Pi, the canonical plugin's agy copy finding (DS11), or the two real
  Mirror homes.
- Do not ship `hello` as a product example; it is this story's fixture, built from
  the guide.

## Acceptance Behavior

```text
Given mirror-mind@0.36.0 from the registry in a scratch prefix with a space in its
  path, a scratch Mirror home with review-copy (real body) and hello installed by
  `mirror extensions install`, and each runtime wired by the canonical plugin's
  printed steps and the extensions plugin's printed step, nothing else
When `live <runtime> review-copy` sends one turn invoking ext-review-copy in the
  runtime's spelling on the fixture copy with `gemini lite` and a report path in the
  scratch directory, and `live <runtime> hello` sends one turn invoking ext-hello with
  this run's canary
Then for each of Claude Code, Codex, Antigravity, and Grok Build, `verify` reads:
  both skills listed by the runtime's own reader after the wiring and not before;
  at least one `consult` call in the scratch ledger from the review-copy session and
  the report at the named path; the canary in ext_hello_pings from the hello
  session; the runtime's interface in conversations for both sessions; the turn
  classified as a find from the loaded skill, not from a disk search —
  or, for a cell that cannot be measured headless, the TUI session's reads and the
  reason, recorded with version, binary, and date
And `untouched` reports zero changes against the baseline of the real ~/.claude,
  ~/.codex, ~/.gemini, ~/.grok, ~/.agents, and the extensions/ and runtime/ trees of
  both real Mirror homes, and `clean` leaves no scratch login behind
```

## Validation Route

**Automated.** The route writes no product code, so: `npm test`, `node
ts/scripts/checkDocLinks.ts`, and `bash route.sh static` (the fixture installs and
validates through the checkout's `mirror`; `turn.js` classifies the two committed
transcripts as find and search; the evidence files parse; the DS5 row names this
story) — green once, to show the tree is as it was.

**Navigator-visible, in order; the Driver runs the steps that need no login, the
Navigator the logins and the agy TUI session if headless denies it.**

0. `bash route.sh setup`, `bash route.sh probe`. Expected: the registry tarball
   installed at `<prefix with space>/lib/node_modules/mirror-mind` at 0.36.0; four
   runtimes with version, binary, date; the readers named. Pass: all four present.
   Fail: a binary absent, a reader that does not run, or a version that is not
   0.36.0.
1. `bash route.sh install`. Expected: `review-copy` and `hello` installed, migrations
   applied, `plugin: mirror-ext-us3user 0.1.2, 2 skills` and four `not wired` lines
   naming the steps. Pass: both installed, the plugin at generation 2 with two
   skills. Fail: a refused install.
2. `bash route.sh login claude`, `login codex`, `login agy` — the Navigator's, once
   each, inside the route's scratch login directories (TS1's mechanics; Grok reads
   `auth.json` in place). Expected: each runtime answers `ready` to a probe turn.
3. `bash route.sh wire <runtime>` ×4. Expected: before, every reader "not listed";
   after, both skills listed. Pass: all four list both. Fail: a step the runtime
   refuses for a reason the record cannot name.
4. `bash route.sh live <runtime> review-copy` ×4, `live <runtime> hello` ×4, one
   retry per miss with both readings kept, the agy cell with
   `--dangerously-skip-permissions` and as `tui` only if that still denies. Expected
   per session: the runtime's model id, exit 0, the before-counts taken, the
   classifier's reading. Spend cap: OpenRouter US$ 0.50 for the whole story
   (`gemini lite`, one model per session), Grok US$ 1.00; `live` reads both sums before
   each turn and refuses past a cap.
5. `bash route.sh verify <runtime>` ×4. Expected: the five reads above per runtime,
   each a delta against the session's before-count; the report carrying the ledger's
   model id; the agy `interface` read as one open conversation per session; the two
   spend sums. Pass: every read as stated, or a miss diagnosed into its kind with the
   measurement. Fail: a `consult` call missing with no diagnosis, a ping missing with no
   diagnosis, an `interface` row missing for a runtime whose hooks were wired.
6. `bash route.sh clean`, `bash route.sh untouched`. Expected: no route process
   running, the scratch directory and every borrowed login gone, the keychain entry
   named if Claude Code left one; zero changes against the baseline; the real homes'
   conversation counts unmoved; any new `*_AI_Reviews_*.html` in the real `~/Downloads`
   named for the Navigator. Pass: zero changes, counts unmoved. Fail: any change, a
   moved count, or a credential copy still present.

E2E decision: required. The eight live sessions are the E2E; nothing short of a
model on each installed runtime, from the shipped package, invoking the real skill
and doing its work, proves this story.

## Implementation Contract

- Use TDD or characterization tests for behavior changes when testable. This story
  changes no product behavior; the route and the fixture are the deliverable, and the
  evidence is the test.
- Keep changes scoped to `CV21.DS5.US3`: the story package, `evidence/`,
  `fixtures/hello/`, the DS5 index row.
- Do not use git add .; commit only story-scoped files.
- Follow the project's development guide: docs/process/development-guide.md.

## Stop Conditions

- scope_change_detected — a product defect the route finds (a step `mirror` prints
  that does not work, a skill the plugin does not carry, a hook that does not log):
  stop, capture a CR, and ask whether to fix it here (one line) or there.
- plan_rule_conflict
- failing_required_check_without_clear_fix
- navigator_decision_needed — a login that cannot be made; a runtime whose headless
  mode cannot execute and whose TUI session the Navigator declines; a spend cap
  reached; a runtime whose version changes between steps.
