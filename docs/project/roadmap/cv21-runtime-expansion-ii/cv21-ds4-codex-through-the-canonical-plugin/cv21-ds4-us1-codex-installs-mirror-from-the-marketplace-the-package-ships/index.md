# CV21.DS4.US1 — Codex installs Mirror from the marketplace the package ships

**Status:** ✅ Done
**Type:** User Story
**Delivery Story:** CV21.DS4 — Codex Through The Canonical Plugin

---

## User Story

As a person who installed Mirror Mind with `npm install -g` and uses Codex,
I want `mirror init` to hand me the two commands that install Mirror as a Codex plugin
from a marketplace the package itself carries,
So that Codex gets the skills, the hooks, and the MCP server the way Claude Code does,
and I no longer link a skills directory, link `AGENTS.md`, and start Codex through a
wrapper script.

## Outcome

The npm package ships `.agents/plugins/marketplace.json`, a Codex marketplace with one
local plugin, `plugins/mirror-mind`. `mirror init` prints
`codex plugin marketplace add "<pkg>"` and `codex plugin add mirror-mind@mirror-mind`
as Codex's wiring. On the installed Codex, from a scratch `CODEX_HOME` with no skills
link and no `AGENTS.md`, those two commands install the plugin, `codex plugin list`
shows it, the rendered prompt carries all 25 `mm-*` skills, and `codex mcp list` names
the `mirror-mind` server. The manifest is guarded in the pack contents and by a test
that ties it to the plugin manifest.

## Acceptance Behavior

```text
Given the package installed in a scratch prefix, and codex on the PATH
When the user runs mirror init <name>
Then the Codex wiring reads
     1. codex plugin marketplace add "<prefix>/lib/node_modules/mirror-mind"
     2. codex plugin add mirror-mind@mirror-mind
And no line names ~/.codex/skills, ~/.codex/AGENTS.md, or scripts/codex-mirror.sh

Given a scratch CODEX_HOME with no skills link and no AGENTS.md
When the user runs the two printed commands against the installed Codex
Then codex plugin list shows mirror-mind installed from marketplace mirror-mind
And codex debug prompt-input hello, from an empty project directory, renders one mm-*/SKILL.md
    per skill directory in the installed plugin (25 today)
And codex mcp list shows the mirror-mind server
And codex plugin remove and codex plugin marketplace remove leave no cache and no config entry

Given a project directory carrying the tree's .agents/plugins/marketplace.json
When Codex reads it with no user action
Then it installs and enables nothing (listing it is fine; anything more is a Navigator decision)

Given the packed tarball
When checkPackContents and smoke_npm_package run
Then .agents/plugins/marketplace.json is in the package, parses, and points at the plugin
And .agents/skills/ is not in the package
```

## Scope

- `.agents/plugins/marketplace.json`, generated by `buildClaudePlugin.ts` beside
  `plugin.json` and drift-guarded by `--check`; shipped through `package.json` `files`
  and required by the pack-contents guard.
- `ts/src/runtime/wiring.ts`: Codex's two steps become the marketplace install, and
  `init`'s and the wiring's tests follow.
- `scripts/smoke_npm_package.sh`: a static step that finds the manifest in the installed
  package and resolves its plugin path.
- The docs that describe what `init` prints: Getting Started §6 and its Codex section
  (with what a v0.32.1 user undoes, and the two remove commands), the
  runtime-interface spec's wiring table, `AGENTS.md`'s Codex skill form, and one
  decision.
- `route.sh` in this package: `static`, `codex`, and `workspace` steps, the last two on
  the real binary with no model call.

## Out Of Scope

- The wrapper, its hook wrappers, the `codex:*` hook family, `smoke_codex.sh`, their
  guards, and the CI step: TS5, once US4 shows parity.
- A live model session: US4.
- SessionEnd's bound (TS2), the `$`-skill rule (TS3), the plugin cache after an update
  (TS6).
- The plugin itself: hooks, `hooks.json`, manifest, MCP entry. Claude Code's wiring.

## Validation

Automated: the suite, `checkPackContents`, `checkDocLinks`, `smoke_npm_package`.
Navigator: `bash route.sh static` (what `init` prints, from a scratch install),
`bash route.sh codex` (the install and its removal on the installed Codex, scratch
`HOME` and `CODEX_HOME`, version and binary recorded), and `bash route.sh workspace`
(what Codex does with a project's marketplace file, unprompted). Details in
[plan.md](plan.md) and [test-guide.md](test-guide.md).
