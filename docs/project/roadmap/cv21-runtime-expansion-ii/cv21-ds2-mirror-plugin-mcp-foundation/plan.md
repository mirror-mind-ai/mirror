# Delivery Story Plan — CV21.DS2

**Journey:** mirror
**Method:** ariad
**Cadence:** stepwise
**Navigator Flow Unit:** delivery_story

## Delivery Story

Mirror Plugin & MCP Foundation

## Objective

The canonical plugin works as it is on Claude Code, Codex, and Grok: its hook commands quote the plugin root, its MCP entry starts without placeholder expansion, the inject hook recognizes Mirror Mode's explicit form in every runtime's skill syntax, and the shared hooks log each session under its own runtime, replies included from Stop.

## Child Work Packages

- CV21.DS2.TS5 — Hook commands quote the plugin root
- CV21.DS2.US6 — The MCP server starts wherever the plugin is installed
- CV21.DS2.US7 — Mirror Mode's explicit form works from every runtime's skill syntax
- CV21.DS2.US8 — Every runtime's session is logged under its own name, replies included

Already done and not reopened: US1, US1b, US2, and TS4. They stay in the candidate table
as the evidence DS2 builds on. US3 (status line) was dropped by DS12.

## Prepare

What the work starts from, read from the working tree on 2026-10-13. The installed
runtimes are the versions DS12 measured: Claude Code 2.1.296, Codex 0.162.1, Grok 1.0.52.

- **The plugin.** `plugins/mirror-mind/.claude-plugin/plugin.json` is generated by
  `ts/src/guards/claudePlugin.ts`, which a drift guard checks. Its `mcpServers` entry is
  `${CLAUDE_PLUGIN_ROOT}/mcp/launch.sh`. `hooks/hooks.json` and `mcp/launch.sh` are
  hand-authored. The four hook wrappers are generated by
  `scripts/generate_hook_wrappers.sh` in their bin form, and run
  `mirror-hook claude:<hook>`.
- **TS5 baseline.** `claude plugin validate plugins/mirror-mind` passes with 4 warnings,
  one per unquoted `${CLAUDE_PLUGIN_ROOT}` hook command. This was re-measured during
  planning with a scratch `CLAUDE_CONFIG_DIR`, and it matches DS12.TS1 static 1. The
  validator offers an exec form (`args`) as the alternative, but Grok skips any handler
  that sets `args` (Grok's bundled guide, `10-hooks.md`). Quoting is the only form that
  works on all three runtimes.
- **The hook timeouts.** Claude Code and Grok read `timeout` in seconds. The plugin's
  `15000` and `30000` are 4 and 8 hours, so no hook ever times out today. The SessionStart
  hook runs the full session maintenance (stale-orphan closes, Pi backfill, retitling,
  extraction: LLM calls) before it prints the Operating Instructions, so a literal 15
  would cut the instructions off.
- **Inject.** `ts/src/hooks/claude.ts` matches `/^\/mm:mirror/` and nothing else
  (DS12.TS1 L4, TS2 L10).
- **Logging.** `claude:user-prompt` does not read stdin; it lets the front-door route
  read fd 0. That route labels every conversation `claude_code` and skips prompts that
  start with `/`. No Stop hook exists. Replies reach the database only through
  SessionEnd's Claude-transcript backfill, which fills only conversations that hold no
  assistant message yet.
- **Where a label is born.** `conversations.interface` is written once, at creation. A
  conversation is created by the prompt logger, or by the Mirror Mode path
  (`bindConversationContext` in `orchestration.ts`, which takes
  `session?.interface ?? "claude_code"`). The session row the inject hook creates has no
  interface. `guessRuntimeSessionId` ignores rows without one, so a session-less
  `mirror mirror load` from the skill guesses the most recent *other* session, which is
  how DS12.TS2 L9 happened.
- **Mirror turns today.** On Claude Code a Mirror turn is a slash turn: its prompt is
  skipped, the skill's `mirror mirror load` binds a conversation, and SessionEnd's
  backfill records the answer. The `mm-mirror` skill's step 3 relies on that.
- **What each runtime hands a hook:**
  - **Codex.** Payloads carry `session_id`, `turn_id`, `transcript_path`, and
    `last_assistant_message` at Stop (TS2 L11). Codex does not expand the placeholder in
    an MCP command (L6). The plugin's SessionEnd never reached Mirror (L8). Async hooks
    run synchronously (L2).
  - **Grok.** Payloads carry snake_case and camelCase fields, `promptId` on turn events,
    and `lastAssistantMessage` at Stop (TS4 L8). Grok's runner sets `GROK_HOOK_EVENT` and
    `GROK_SESSION_ID` on every hook. An extra observe-only Stop fires at session end,
    without `promptId`. UserPromptSubmit context is discarded (L3). Handlers that set
    `async` run in the foreground, with a load error naming the field. `lastAssistantMessage`
    is clipped at 32,768 characters with a `… [+N chars]` marker.
  - **Claude Code 2.1.296.** The installed binary builds the Stop input with
    `last_assistant_message`. Its common hook input names `session_id`,
    `transcript_path`, `cwd`, `prompt_id`, `permission_mode`, `agent_id`, `agent_type`,
    and `effort`, but no `turn_id`. Both were read from the binary during planning.

Risks:

- a runtime that expands variables inside MCP `args` could rewrite a shell locator (US6);
- a detection marker that moves in a later runtime version (US8);
- a Stop hook that printed JSON or exited 2 would keep the agent working instead of
  logging;
- Claude Code runs `log-user-prompt` with `async`, so a very short turn could reach Stop
  before its prompt is logged;
- the live sessions need logins inside scratch homes, and they cost model turns.

## Scope

1. **TS5: quote the plugin root, and make the timeouts seconds.** Every command in
   `plugins/mirror-mind/hooks/hooks.json` becomes `"\"${CLAUDE_PLUGIN_ROOT}/hooks/<name>.sh\""`,
   and the checkout's `.claude/settings.json` quotes `$CLAUDE_PROJECT_DIR` the same way.
   The `timeout` values become seconds: SessionStart `300`, because its maintenance calls
   the LLM and the old value never cut it; inject `30`, as the old value intended; the
   loggers keep the runtime default. A test fails if any plugin hook command leaves
   `${CLAUDE_PLUGIN_ROOT}` unquoted, or sets a `timeout` above 300, so US8's new handler
   cannot regress either.
2. **US6: the MCP entry starts without `${CLAUDE_PLUGIN_ROOT}`.** The entry is chosen by
   measuring it, first, before any other child:
   - **Preferred: an inline locator.** `command: "/bin/sh"`,
     `args: ["-c", "<locator>"]`. The locator runs the search `mcp/launch.sh` runs
     today: `MIRROR_BIN`, then the PATH, `~/.nvm/current/bin`, `/opt/homebrew/bin`,
     `/usr/local/bin`; `MIRROR_NODE` first for node. It is POSIX `sh`, with no `${…}`
     and no positional parameters, and a test asserts that on the generated text. It
     keeps the reach a GUI launch needs, and keeps the one stderr line and exit 1 when
     `mirror` or `node` is missing.
   - **Fallback: the bare bin.** `command: "mirror"`, `args: ["mcp"]`. This is used if any
     of the three runtimes does not pass the locator through verbatim. The trade-off is
     written down: a runtime whose PATH lacks the npm bin (a GUI launch) does not start
     the server. The hooks are unaffected, and `runtime diagnose` already names a
     missing `mirror`.
   - **The measurement.** In scratch homes, with no model call, a plugin copy carrying
     the candidate entry is rendered through `claude plugin details`,
     `codex mcp get mirror-mind`, and `grok plugin details` / `grok inspect --json`. The
     entry is also run exactly as written, with `initialize` and `tools/list`, which is
     what a runtime that expands nothing does. The same run prints which of `PATH`,
     `HOME`, `MIRROR_BIN`, and `MIRROR_NODE` reached the server, because a runtime may
     hand an MCP server a reduced environment, and then the search order is what saves
     it.
   - **The GUI launch, proven.** Two tests on `buildManifest`'s output: run the entry
     under `env -i` with a minimal PATH and `MIRROR_BIN` set, and it answers
     `initialize`; run it with no `MIRROR_BIN`, and it prints the one line and exits 1.
   - **One body.** The entry is emitted by `buildManifest`, so the drift guard covers
     it. `mcp/launch.sh` retires, because no manifest names it anymore. Its tests move
     to the entry, including the assertion that its search directories equal the hook
     wrappers', so the two copies cannot drift. The smokes, `retiredSurfaces`,
     REFERENCE, and the runtime-interface spec follow. The docs say a Codex user
     re-installs the plugin to receive the new entry: Codex copies a plugin into its
     cache at a version, where Claude Code's `@skills-dir` reads it in place.
   - **`runtime diagnose`** running the same locator is a follow-up Change Request, not
     this story.
3. **US7: the inject hook knows every explicit form.** A prompt that opens with the form
   is recognized. The form is a `/` or `$` sigil, then an optional `mirror-mind:`
   namespace, then `mm:mirror` or `mm-mirror`, then whitespace or the end of the prompt.
   That covers:
   - `/mm:mirror`: standalone Claude Code;
   - `/mirror-mind:mm-mirror`: the Claude Code plugin (TS1 L4);
   - `/mirror-mind:mm:mirror`: Claude Code's menu form (TS1 static 6);
   - `$mirror-mind:mm:mirror`: the Codex plugin (TS2 L10);
   - `/mm-mirror`: Grok (TS4 L5);
   - `$mm-mirror`: Codex's own skill form.

   The grammar is one function, and US8 reuses it to tell a Mirror turn from a command.
   The query passed to `mirror load` is the prompt with the form stripped. A longer
   skill name (`/mm-mirrors`) or a form that is not at the start of the prompt is not
   recognized. The `mm-mirror` skill's hook note and the runtime-interface spec name the
   forms, and the note says the identity block is loaded twice on an explicit turn, by
   the hook and by the skill; dropping one is DS4's. On Grok the form is recognized, but
   Grok discards UserPromptSubmit context (TS4 L3). Mirror Mode there still comes from
   the skill, as it does today.
4. **US8: the shared hooks know their runtime, and log replies from Stop.**
   - **The payload is read once.** The `user-prompt` and `stop` entries read stdin, and
     hand the payload to the logger route explicitly. Nothing reads fd 0 twice.
   - **Detection.** One function returns:
     - `grok_build` when Grok's runner variables are set, or the payload carries
       Grok's `hookEventName`;
     - `codex` when the payload carries Codex's `turn_id`;
     - `claude_code` otherwise.

     Payload fields are read in both spellings: `session_id`/`sessionId`,
     `last_assistant_message`/`lastAssistantMessage`, and the turn id as `prompt_id`,
     `turn_id`, or `promptId`. Detection gates no write; a label is attribution.
   - **The label is stamped on every prompt, skipped or not.** The user-prompt entry
     writes `runtime_sessions.interface` before anything else can create the
     conversation, so a conversation the skill's `mirror mirror load` creates inherits
     the right label, and the hook's own session is the one `guessRuntimeSessionId`
     finds.
   - **A Mirror turn is a conversation turn.** A prompt that opens with a Mirror form
     (US7's grammar) is logged with the form stripped: the question, not the command. A
     bare form with no question logs nothing. Any other slash command stays skipped, as
     today. Codex's `$`-skill turns other than Mirror are left as they are (Non-Goals).
   - **The turn id is stored.** The prompt's and the reply's `messages.metadata` carry
     the runtime's turn id when the payload has one. No migration: the column is JSON
     and NULL today.
   - **A Stop handler** is registered in the plugin's `hooks.json` and in the checkout's
     `.claude/settings.json`, `async` on Claude Code like the prompt logger. Grok also
     runs a trusted project's `.claude/settings.json` (TS4 static 5), so opening this
     checkout in Grok logs replies into the developer's Mirror home, as the prompt hook
     already does. It runs through a new generated wrapper pair (`claude:stop`, tree
     form and bin form).
   - **Which replies are logged.** The handler logs the Stop message as the assistant
     turn when it answers a logged prompt: by turn id when both carry one, else when the
     conversation's last message is a logged prompt, ordered by `created_at, rowid`.
     That one rule:
     - pairs every reply with its prompt, Mirror answers included;
     - skips the reply to a command turn, whose prompt is not logged;
     - skips Grok's session-end Stop, and any repeat of a turn already answered.
   - **What it does not log,** each pinned by a test: an empty or missing message (an
     interrupted or tool-only turn); a second Stop for a turn already answered, so when
     another Stop hook keeps the agent working, the first answer stands and the
     continuation's is not recorded (a known limitation, accepted); anything while mute
     is on or the discard marker holds. Grok's clip marker is stored as received.
   - **A skip is counted.** When nothing is waiting for the reply, the handler writes one
     `hooks.log` line naming the fact, never the text. `route.sh check` counts those
     lines. If the live sessions show any, `async` comes off the prompt logger and the
     one Node start is paid, as the inject hook already pays it.
   - **The Stop handler never blocks or extends a turn.** It writes nothing to stdout
     and exits 0 whatever happens. On failure its `hooks.log` line carries neither
     prompt nor reply, and a test asserts that.
   - **SessionEnd's transcript backfill stays as the fallback.** It fills only
     conversations without an assistant message, so a Claude Code session is not
     recorded twice.
5. **Docs.**
   - DS2's index: the June Scope and Done Condition are restated to the reshaped
     outcome. That means no Python server, no `pyproject.toml`, and no status line. The
     US6 row reads "starts on Codex and Grok from an entry that names no
     `${CLAUDE_PLUGIN_ROOT}`; Grok's attachment is DS10's (DS12.TS4 L6)".
   - The `mm-mirror` Claude skill: step 1's hook note names the forms and the double
     load; step 3 says the runtime's Stop hook records the reply.
   - The runtime-interface spec: the inject forms, the Stop hook, the MCP entry, the
     reply rule, and `grok_build` among the established labels.
   - REFERENCE: the MCP entry and the `MIRROR_BIN` / `MIRROR_NODE` rows.
   - Three decision entries: the MCP entry chosen, Mirror turns as conversation turns
     with replies paired from Stop, and the timeouts.
   - The worklog.
   - TS5, US6, US7, and US8 packages, each authored as it lands: story, outcome,
     acceptance, and status. Each child closes Done in its package and in the candidate
     table.

## Non-Goals

- **Grok's MCP attachment.** Grok starts the server but does not attach it (DS12.TS4 L6,
  cause unknown). The CV21 index gives that investigation to DS10. If the new entry
  happens to attach on Grok, the finding is recorded and nothing more.
- **Codex's SessionEnd.** It never reached Mirror (TS2 L8), and this plan does not fix
  it. Validation records whether a Codex conversation closes. A fix belongs to DS4 or
  to a Change Request.
- **Grok's SessionEnd budget.** Grok bounds a SessionEnd hook without its own `timeout`
  at 1.5 seconds, which the close tail cannot meet. Recorded for DS10.
- **Per-turn injection on Grok.** Grok does not offer it (L3).
- **The skip rule for `$`-skill turns.** Whether a `$`-skill turn on Codex, other than a
  Mirror form, is skipped like a `/` turn is not changed here. It is noted for DS4.
- **Dropping the second context load on an explicit turn.** DS4's.
- **`runtime diagnose` running the MCP locator.** A follow-up Change Request.
- **Other Delivery Stories' work:**
  - install flows and marketplace, plus `mirror init` wiring for Codex and Grok (DS4,
    DS10);
  - Antigravity's native layer (DS7);
  - the parity matrix and the docs refresh (DS11).
- **The session-less `mirror mirror log` defect** (TS2 L9). That core defect is CR100's.
- **No push, release, or publication.** Release intent is yours to record.

## Validation Route

E2E is required. It consists of live sessions on Claude Code, Codex, and Grok, run by the
Navigator. They use DS12's isolation:

- this tree's package is installed into a scratch npm prefix;
- each runtime gets a scratch `HOME` or config directory, mode `700`;
- the scratch Mirror home has no provider key;
- each runtime gets at most two turns, six in total;
- `clean` deletes the scratch directory, logins included, and is run even when a step
  failed.

The route is a `route.sh` in this package, adapted from DS12's.

- **During implementation, the Driver** runs `npm run typecheck`, `npm run lint`, and
  `npm test`, then:
  - `bash scripts/generate_hook_wrappers.sh --check` and the plugin drift guard;
  - `scripts/smoke_claude_plugin.sh` and `scripts/smoke_npm_package.sh`;
  - the route's static steps:
    - validation on Claude Code and Grok, with the validator versions recorded;
    - the MCP entry as each runtime renders it, and as written, with the variables
      that reached the server;
    - the plugin's inject wrapper fed each explicit form, printing the bytes of
      context out. Before this work only `/mm:mirror` returns any (TS1 static 6);
    - **the scripted journey**, per runtime shape: recorded payloads for
      `[Mirror turn, Stop, ordinary turn, Stop, a repeat Stop, a command turn, Stop,
      SessionEnd with a transcript]`, piped through the wrappers into the scratch
      database, against an expected message list written before implementing. Grok's
      shape adds its session-end Stop; Claude Code's adds a transcript the backfill
      must not double.
- **At Validation, the Navigator:**
  1. runs `route.sh live-claude`, `live-codex`, and `live-grok`, each with one Mirror
     Mode turn in that runtime's explicit form and one ordinary turn;
  2. runs `route.sh check`, which prints for each runtime:
     - the conversation's `interface`, and the runtime session's;
     - its messages, with roles and turn ids in order, and one reply's text to compare
       with what the Navigator saw;
     - the count of skipped-reply lines in `hooks.log`;
     - whether the MCP server started: on Claude Code and Codex, the tools the model
       listed; on Grok, its `logs/mcp/mirror-mind.stderr.log`, empty when the server
       started cleanly, or holding the one locator line when it did not;
     - whether the Codex conversation closed, recorded as a finding;
  3. runs `route.sh untouched`, then `route.sh clean`.

Expected observations, and pass and fail conditions, are in
[test-guide.md](test-guide.md).

## Implementation Contract

- **US6's measurement comes first.** It is a spike bounded to the static steps, and its
  result decides the entry before TS5, US7, and US8 are written. The implementation of
  US6 comes last, because it also carries the docs.
- **TDD for every behavior change.** Detection, the reply rule, the Stop handler's
  output, the inject grammar, the Mirror-turn logging, the turn-id metadata, and the
  generated MCP entry each get their tests first. The tests are built from the recorded
  payload shapes: DS12 TS1, TS2, and TS4, and Grok's guide.
- **The hook contract holds.** A hook never fails the turn. It writes one `hooks.log`
  line when it cannot do its job, and never writes the prompt or the reply there. The
  Stop hook prints nothing.
- **Generated stays generated.**
  - Wrappers come only from `generate_hook_wrappers.sh`.
  - `plugin.json` comes only from `claudePlugin.ts`.
  - Plugin skill copies come only from `.claude/skills/`.
- **Isolation for every runtime probe.** Probes use scratch homes at `700`. No real
  config is mutated, and `untouched` compares checksums of the real configs.
- **Cost.** The Driver makes no model calls. The Navigator's turns are capped at two per
  runtime.
- **The evidence rule** holds for every runtime fact recorded: version, binary, date,
  and command.
- **Scope discipline.** Changes stay inside the four children and their docs. Anything
  else becomes a Change Request or a reshaped roadmap row.
- **Commits.** Small, per child, in English, explaining why. Nothing is pushed or
  released.

## Stop Conditions

- Both MCP entry designs are rewritten or refused by a runtime: stop and ask.
- The detection markers cannot separate two runtimes on the evidence: stop and ask
  before guessing a label.
- A live check shows a reply logged twice, or under the wrong prompt: stop.
- An installed runtime version changes mid-story: re-run its static steps and record both
  readings.
- A step can only run by changing a real runtime config: stop and ask.

## Delivery Sequence

1. US6 measurement: the scratch install, the candidate entry on the three runtimes, the
   decision recorded in US6's package.
2. TS5: quote the commands, the timeouts, plus the guard test.
3. US7: the explicit-form grammar in the inject hook, plus the skill note.
4. US8: detection, the payload read once, the session label on every prompt, Mirror
   turns logged, turn ids stored, the Stop route and handler, the wrappers, and the
   registrations.
5. US6 implementation: the generated entry and its tests, the launcher retired, and the
   docs.
6. `route.sh` static steps and the scripted journey, and every Driver check, green.
7. The Navigator's live sessions, then Validation.

## Decisions Taken At Approval

Recorded on 2026-10-13, after the plan review by the engineer, devops-engineer,
quality-assurance, security-engineer, database-architect, and ai-engineer lenses.

1. **US6's candidate row** drops "and Grok attaches it"; Grok's attachment is DS10's.
2. **US6's entry:** the inline locator, with the bare `mirror mcp` as the measured
   fallback.
3. **The reply rule:** Mirror turns are conversation turns, logged with the form
   stripped, and a reply is logged when it answers a logged prompt. The pairing-only
   rule first proposed was withdrawn because it dropped the Mirror answers on Claude
   Code, which today's backfill records.
4. **The timeouts** are folded into TS5.
