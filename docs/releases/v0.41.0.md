# v0.41.0 — A Persona When the Subject Asks for One

**Date:** 2026-11-08

## Highlights

- **A turn's persona follows its subject, or there is none**
  ([CR203](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr203-route-a-turns-persona-by-its-subject-and-let-it-have-none.md)).
  In Mirror Mode, on the delta of an ordinary turn and on the full load alike, the persona
  is, in order: the one you named (`mirror load --persona`); the router's answer, a
  Decisions model through OpenRouter's Decisions API asked which persona the subject
  belongs to and whether it belongs to any, taken only at or above a threshold; the persona
  the turn's Journey names as `default_persona` in its metadata; or none. It is never the
  session's by inheritance.
- **None is said, not left silent.** A turn with no persona delivers
  `persona: none` and the clause
  `answer as the mirror; no persona this turn: do not sign, and do not answer as an earlier persona`,
  so the model does not keep signing as the last persona it answered as.
- **Every routing failure is none, and the turn goes on.** No key, a timeout, a refusal, a
  malformed answer or a persona that does not exist each give a turn with no persona. One
  attempt, bounded like reception (`MEMORY_LLM_TIMEOUT_RECEPTION`, 10 s by default).
- **Two settings.** `MEMORY_PERSONA_ROUTER_MODEL` (`liquid/d1-ultra`) and
  `MEMORY_PERSONA_ROUTER_THRESHOLD` (`0.6`), in [`REFERENCE.md`](../../REFERENCE.md); an
  invalid value reads as unset.
- **The host gets the persona's name**
  ([CR204](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr204-hand-the-host-the-personas-name-with-its-id.md)).
  `deliverMirrorContext` in `mirror-mind/desktop` returns `personaName`, the persona's own
  `name` from its metadata, or `null`; `persona` stays the id. Additive.
- No schema change, no migration.

## Where We Started

A keyword count chose every turn's persona, and when no keyword scored, the session's
persona kept answering. Measured on the maintainer's own data over five days (550
deliveries), every turn had a persona, the persona changed on one turn in three, and
specialists from unrelated domains answered: health, customer support and QA personas on a
book-writing Journey. The maintainer's criterion: a wrong persona is worse than none,
because it puts a false specialist into the answer, while no persona only loses one
domain's lens and keeps identity, voice and memories.

## What Changed

**One router for both paths.** `ts/src/mirror/personaRouter.ts` owns the Decisions route,
which OpenRouter marks `alpha`: its request and answer shapes live in that module and a
contract test pins them, so a change in the route fails a test, not a turn. The doorman's
delta and the full load call the same rule, so the two cannot disagree. The delta asks the
router and embeds the prompt at the same time, so the call adds no wait of its own to the
delivery. Each persona is offered with its own `description`, else its generated
descriptor, else the start of its content.

**The session records the turn's answer.** A session's persona is now the last turn's,
none included. Which persona sections the conversation already holds is kept apart
(`doorman_personas` in the session's metadata), so a section is delivered the first time
its persona answers and not again; a full load starts that list over, and a compaction
clears it.

**Reception still runs** on a full load, for the Journey and the turn's shaping. It no
longer chooses the persona. Its prompt is unchanged.

**The ledger.** Each routing call writes one `llm_calls` row, `role = persona_routing`,
with the model, latency and cost, and an empty prompt and response in every logging mode:
the subject of your turn is not the ledger's to keep.

**Measured before the release.** The router was chosen by an eval of 100 labelled turns
from the maintainer's production data
([report](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr203-persona-routing-eval-2026-11-07.md)).
The same 100, rerun through this release's code on a copy of a home with 28 personas: 93
right, 3 wrong, 4 missed (the keyword router: 35 wrong), at 0.61 s median and 1.32 s at
p95, about US$ 0.00008 per turn. The private turns stay out of this repository; a
synthetic set runs in CI.

**Model-behavior gate.** This release changes no extraction model, embedding model or
`prompts.ts` prompt, so the gate's letter does not apply; it does add a model call and a
line the model reads, and the rerun above is its evidence in place of `eval --all`, which
does not probe routing.

## Conscious Exclusions

- **No command sets a Journey's `default_persona` yet.** The Core reads it; setting it is a
  follow-up. Two of the rerun's three wrong picks are a Journey's own writing persona on
  turns that asked for none, the case a default resolves.
- **The no-persona clause is a first wording**, one constant (`NO_PERSONA_CLAUSE`), to be
  settled in prompt review.
- **`detect-persona` stays** as a command, an MCP tool and a package export. It no longer
  decides a turn.
- **Reception's prompt still lists the personas**: its bytes are digest-pinned, and
  changing it is its own decision.
- **A full load's worst case grows**: reception, then routing, each bounded at 10 s. A
  delta's is unchanged.
- **Two personas covering one domain** remain content for their owner to merge.

## Upgrading

```bash
mirror runtime update
```

Nothing to configure: the router uses the OpenRouter key Mirror already reads. The routing
calls are the `persona_routing` rows of `mirror inspect llm-calls`. Turns without a persona
are expected: they answer as the mirror, unsigned.
