# v0.35.0 — Four Runtimes, One Successor

**Date:** 2026-10-18

## Highlights

- **Gemini CLI is no longer a Mirror runtime; Antigravity is its successor**
  ([decision](../project/decisions.md#gemini-cli-is-retired-and-antigravity-is-its-successor)).
  The four `.gemini/hooks` wrappers, the `gemini:*` hook family, the two
  Gemini CLI steps `mirror init` printed, and the Gemini smoke no longer ship
  (CV21.DS8.US1). The package's description and keywords, and every
  runtime-facing document, name Pi, Claude Code, Codex, and Antigravity
  (CV21.DS8.US2).
- **The gate was met first.** v0.33.0 gave notice that the integration would
  be removed "only once Antigravity gives a Gemini CLI user what they have
  now". CV21.DS7.US4 measured that on agy 1.4.2, live: all of Mirror's
  skills, the Operating Instructions at session start, Mirror Mode context
  injected once per user turn, every turn logged and the conversation closed,
  setup in one step against Gemini CLI's two — and MCP reachable, which the
  Gemini CLI wiring never had.
- **The cutoff is written where a user reads it before it happens to them**:
  the section below, the Antigravity section of
  [Getting Started](../getting-started.md#antigravity), and a
  [troubleshooting entry](../process/troubleshooting.md#gemini-cli-runs-a-mirror-hook-that-no-longer-exists)
  for the symptom a Gemini CLI user would meet.
- **A retired-surface guard keeps the removal removed.** `.gemini/` can never
  ship again from this package: the row is enforced on every push and by the
  release tripwire. That matters because `mirror init` once told users to
  write absolute paths into that directory into their settings — a standing
  instruction to execute whatever a later release might put there.

## Where We Started

v0.32.1 shipped Gemini CLI as one of four supported runtimes, at L4 parity,
wired by two documented steps. On 2026-09-25 the Navigator retired it —
Google had set a deprecation date for the Gemini Code Assist backend for
individuals, and Antigravity, which imports Claude-format plugins, was the
successor — but the call lived in one story's notes while the release kept
advertising the runtime. The decision was recorded on 2026-10-13, with a
condition: the integration goes only behind a documented cutoff, and only
once Antigravity meets the bar a Gemini CLI user already had. DS7 built the
agy-native layer and measured the bar. DS8 is the cutoff.

## What Changed

**The integration is gone from the package.** No `.gemini/hooks`, no `gemini`
entry in the wiring `mirror init` prints, no `gemini:*` hook names — an
unknown name is noted in `hooks.log` and the turn proceeds, as any unknown
name does. The Gemini smoke and the npm smoke's Gemini section retired with
it; the hook payload reader dropped the one field only Gemini CLI supplied.

**The docs say what ships.** Twenty files: README, Getting Started,
REFERENCE, the Operating Instructions and their plugin copy, the
runtime-interface spec, the welcome spec, the architecture, and the skills
that said "Pi and Gemini CLI". Where a runtime list, a wiring step, or a
parity table had Gemini CLI, it has Antigravity. Where a lesson says what
Gemini CLI taught — the payload-shape bug its smoke caught, the one-JSON-
object rule its hook entries kept — the lesson stays, in the past tense.
Getting Started's subscription table no longer carries a Gemini AI Pro row
and invents no Antigravity row: what Antigravity requires is Google's to
say, and Mirror needs only the `agy` command on your PATH.

**Antigravity's own documentation is unchanged** beyond taking Gemini CLI's
place: DS7 wrote it and measured it.

## The Cutoff: Gemini CLI

**What you keep.** Everything that is yours. Your `~/.mirror-minds/<user>`
home, your identity, your memories, your journeys, and every conversation
you logged — including the ones labelled `gemini_cli`, which stay readable
in `mm-conversations` and `mm-recall` and are never migrated or relabelled.
Only the runtime that reads them changes.

**Removed.** The four `.gemini/hooks` wrappers (`session-start.sh`,
`log-user.sh`, `log-assistant.sh`, `session-end.sh`) and the `gemini:*` hook
family behind them; the two Gemini CLI steps `mirror init` printed (the
skills link, the four hooks merged into `~/.gemini/settings.json`); the
Gemini smoke; the runtime from the package's description and keywords and
from every runtime-facing document.

**Why.** Google deprecated the Gemini Code Assist backend for individuals
(2026-06-18). Antigravity is its successor and imports Claude-format
plugins — the one plugin Mirror already ships. The removal waited for
DS7.US4's measurement on agy 1.4.2: all five items of the bar DS12.TS3 set
PASS, with per-turn injection — the cost the decision feared losing —
carried by agy's `PreInvocation` hook. The one difference that did
materialize: agy has no session-end signal, so a conversation closes when
your next session starts rather than at exit (as Codex's does); logging
parity holds, and memories extract after the close.

**What to do instead.** Install Antigravity, then the one step `mirror init`
prints when it finds `agy` on your PATH:

```bash
agy plugin install "<pkg>/plugins/mirror-mind"    # <pkg> = $(npm root -g)/mirror-mind
```

Your home carries over unchanged — nothing to export, nothing to re-seed.
Same home, same memory, different door. The skills carry the plugin's name:
`/mirror-mind:mm:mirror`, `/mirror-mind:mm:journeys`, and so on.

**What still works.** Gemini *models*. Memory extraction runs on
`google/gemini-2.5-flash-lite` through OpenRouter, and `consult` reaches the
`gemini` family as before. Those are model choices, not the runtime.

**If you do nothing.** After the update, the four `mirror-*` hook commands in
your `~/.gemini/settings.json` point at files that no longer exist, while the
links in `~/.gemini/skills/` still resolve — `.pi/skills` keeps shipping. So
Gemini CLI keeps Mirror's skills and loses logging and Mirror Mode injection.
Said plainly: your Gemini CLI sessions stop being logged and Mirror Mode
stops being injected, and nothing on screen says so. Measured on Gemini CLI
0.61.0 in headless mode (`gemini -p`), 2026-10-18: a registered hook whose
command is missing is skipped silently; the session proceeds. The entries to
delete, in `~/.gemini/settings.json`: `mirror-session-start` (under
`SessionStart`), `mirror-log-user` (`BeforeAgent`), `mirror-log-assistant`
(`AfterAgent`), `mirror-session-end` (`SessionEnd`); and the `mm-*` links in
`~/.gemini/skills/`. Mirror never wrote those files and does not edit them.
Whether Antigravity also reads `~/.gemini/skills/` — which would show a
migrated user the stale links as duplicate skills — was not measured;
remove the links either way.

**To stay on Gemini CLI a while longer.** `npm install -g mirror-mind@0.34.0`
is the last release that carries the integration. The welcome card and
`runtime update` will keep offering the newer version every session; the pin
is a choice to make knowingly, not a quiet state.

## Upgrading

```bash
npm install -g mirror-mind@latest    # or: mirror runtime update
```

**If you used Gemini CLI:** read the cutoff above; the steps are in Getting
Started's Antigravity section. **Every other runtime:** nothing to do. No
migration. Existing homes, sessions, and memories are untouched.

## Also In This Release

- **Typecheck is green on `main` again.** DS7.TS3 left one early return in
  `hooks/agy.ts` without the field it had just added; `tsc --noEmit`, a CI
  gate, refused since. Found by DS8.US1's validation, paid in its own commit.
- **The docs link check is green again.** The plugin's byte copy of the
  Operating Instructions carries a root-relative link that cannot resolve
  under `rules/`; the checker reported it on every `.md` push since DS7.US1.
  The copy's links now resolve where the source lives — not skipped: a link
  the source cannot resolve still fails through the copy.
- **The P1 redaction invariant outlives the runtime it was written against.**
  "A failed hook never writes the prompt or the reply to `hooks.log`" was
  tested through the Gemini CLI hooks; it now runs through the Claude-family
  hooks every plugin runtime shares.

## Conscious Exclusions

- **No second cutoff document.** CV22 needed `pending-cutoffs.md` for eleven
  cutoffs in one release; DS8 has one, and this note is its record.
- **Mirror does not edit `~/.gemini/settings.json` or `~/.gemini/skills/`.**
  It never wrote them. The note and the guidance name what to remove.
- **The Claude plugin smoke's negative probe** still cannot run on a machine
  with a globally installed `mirror-hook` (CR142, D-031): pre-existing,
  local-only, carried.
- **DS5, DS10, DS11** — user extensions on every runtime, Grok through the
  plugin, the contract and docs refresh — are CV21's remaining stories, not
  this release's.

## What We Learned

A retirement that lives in a decision while the release advertises the
runtime has not happened; it happened here in three stories, in order:
remove, then make the tree say so, then tell the user — and the guard that
proves each step split by story, so nothing went red between them. The
sweep found what the inventory missed (a spec line, a history link), which
is what a guard is for. And the one fact this note most needed — what a
user who does nothing will see — turned out to be *nothing*: Gemini CLI
skips a missing hook in silence. That is the strongest reason the cutoff is
written where the user looks, not only here.

## Next Horizon

DS8 closes with this release, and with it the runtime set CV21 set out to
reach: the canonical plugin on Claude Code, Codex, and Antigravity, Pi
through its extension. What remains in CV21 is pulled deliberately from the
CV21 index: user extensions on every runtime (DS5), Grok through the plugin
(DS10), and the contract and docs refresh that folds all of it into one
account (DS11).
