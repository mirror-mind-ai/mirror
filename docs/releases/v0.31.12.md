# v0.31.12 — Bounded Authority and Journey Integrity

**Date:** 2026-08-29

## Highlights

- Accepts natural one-turn story Plan delegation in stepwise/checkpoint cadence
  and declarative bounded story authority in accelerated cadence.
- Preserves exact active-item, generation, level, expiry, single-use, and
  concurrency boundaries while keeping Navigator Validation mandatory.
- Keeps Driver-authored Plan bodies intact through approval and distinguishes a
  Delivery Story's release intent from commit, push, tag, and publication
  authority.
- Adds `mirror.journey-mutation@1.0`, a deterministic and model-free service for
  transactional Journey creation, update, movement, ordering, and guarded
  removal.
- Refuses Delivery Story Done before cursor or artifact mutation when authored DS,
  child, candidate-row, or canonical roadmap status remains non-Done.

## Where We Started

Ariad's safe defaults had become too literal. Even when the Navigator naturally
asked for a Plan and immediate implementation, story-by-story flow stopped for a
second approval; accelerated cadence carried no declarative policy for that same
boundary. The first implementation also risked replacing a useful Driver-authored
Plan at approval time, and release intent could be mistaken for authority to
publish.

At the same time, Journey hierarchy mutation still depended on scattered storage
operations rather than one versioned, model-free transactional contract. The
CV20.DS16 closure then exposed a final trust defect: `done-delivery-story` could
render “Closure coherence passed” while authored roadmap files still said `In
Progress`.

## What Changed

Story Plan preauthorization now records bounded structural authority for one
exact active User or Technical Story. Natural delegation can create and approve a
complete Plan in one flow for stepwise/checkpoint work; accelerated cadence reads
`plan_approval_policy=bounded_story_authority` from method data instead of
receiving authority from a hard-coded profile name. Receipts are generation-bound,
single-use, atomic under concurrent attempts, and never cross Navigator
Validation. The completeness classifier recognizes actual scaffold markers
without treating legitimate domain prose such as “Payment placeholder” as an
unfinished Plan.

Plan approval no longer regenerates or overwrites an authored Plan. Release intent
is persisted and rendered as orientation, but its contract explicitly grants no
commit, push, tag, stable-promotion, or publication authority.

`JourneyAdminService` introduces the versioned `mirror.journey-mutation@1.0`
contract. It exports deterministic registry state and performs hierarchy writes
transactionally without model calls. Parent changes, sibling ordering, protected
historical associations, and projection refresh ordering are checked before a
mutation can leave an orphaned or partially moved Journey.

Delivery Story closure now performs a read-only authored-roadmap preflight before
calling the mutating Done core. Existing packages resolve through heading-based
story identity. Explicit DS and child package statuses, child candidate rows, and
canonical Code/Status table rows must already report Done; otherwise the command
returns project-relative evidence, leaves the cursor unchanged, and creates no
Done artifact. The agent retains semantic ownership of Markdown edits.

## Conscious Exclusions

- Natural Plan delegation does not bypass Navigator Validation, broaden to a
  different story, survive generation mismatch, or authorize external effects.
- Release intent does not authorize commit, push, merge, tagging, stable
  promotion, GitHub publication, or installation.
- Python verifies authored closure status but does not rewrite roadmap prose or
  infer project meaning.
- Journey mutation remains a local Core contract; it adds no hosted service,
  synchronization protocol, model-based planning, or destructive cascade.
- The four pre-existing repository-wide Ruff findings under
  `spikes/ts-search-parity/` are unchanged.

## What We Learned

Good autonomy is not the absence of checkpoints. It is authority represented at
the right granularity: exact scope, explicit policy, bounded lifetime, atomic
consumption, and a visible hard stop where human judgment still matters.

Coherence must also be proven from authored state rather than inferred from a
runtime transition. A Done surface earns trust only when it refuses to speak
more strongly than the files and cursor allow.

## Next Horizon

CV20 can continue refining Ariad's remaining release/push and debt-loop behavior
on top of explicit authority contracts. Journey consumers can adopt the versioned
mutation service without coupling hierarchy administration to model behavior.
The next release boundary should remain driven by a completed story or
maintenance need rather than by this horizon alone.
