# v0.31.10 — Journey Projection Contract

**Date:** 2026-08-25

## Highlights

- Implements public contract `mirror.journey-projections@1.0` in the Python Core.
- Adds `journey-projection capabilities`, `rebuild-operational`, and `inspect`,
  with isolated test-only preparation/publication routes for the immutable
  consumer probe.
- Publishes projection and manifest state with one cross-process lock per Journey,
  fresh manifest merge under lock, atomic replacement, last-valid preservation,
  explicit divergence, and immutable snapshot receipts.
- Adds Extension API `1.1` with `api.journey_projections`, permanently bound to
  the installed extension's identity; extensions cannot select `ariad`, another
  namespace, or a filesystem root.
- Compiles Ariad roadmap, active Delivery work, public Explorer handoffs, and
  canonical Refinement state into deterministic `ariad:operational` documents.
- Refreshes represented state after source commits without making projection
  availability a transaction dependency or rolling durable truth back.
- Passes the unchanged consumer-owned probe with exact normative fixture parity,
  schema/path/namespace attack rejection, atomic consistency, and no production
  data.

## Where We Started

Nautilus needed a stable local reading of Journey state, but Mirror had only
human-facing Markdown and runtime records. A consumer could either parse internal
files directly, depend on private implementation details, or ask Mirror to
surrender mutation authority. None was acceptable. The handoff therefore began
with a consumer-owned contract and acceptance kit rather than a Mirror-owned API
proposal.

The central tension was authority. Ariad documents and lifecycle records had to
remain the source of truth, extensions had to remain inside their own namespaces,
and production callers could identify a Journey but never choose a filesystem
root. At the same time, concurrent Core and extension publishers needed one
consistent manifest rather than a collection of atomic files with lost-update
races between them.

## What Changed

Mirror adopted the contract in layers. Public models, JSON Schema 2020-12
validation, canonical UTF-8 serialization, stable payload-free errors, and honest
capability discovery established the boundary first. The storage kernel then made
publication linearizable per Journey across processes. Every writer acquires the
same Journey lock, rereads the current manifest after acquisition, verifies or
creates an immutable receipt, replaces the projection, and makes manifest
replacement the publication linearization point. Controlled failures restore the
previous pair when possible; unrecoverable states surface bounded divergence and
inspection never repairs implicitly.

Extension API `1.1` exposes that kernel through a façade bound at construction to
`extension_id`. Envelope namespace and producer identity must match that binding,
and `ariad` remains Core-only. A raw extension database connection grants no
projection filesystem authority.

The Ariad compiler reuses shared roadmap grammar and emits only represented,
public durable state. Authored hierarchy order is preserved. Artifact paths are
Journey-relative and confined. Explorer source conversations, prompts, raw
reasoning, environment state, transcript bodies, and private narrative evidence
are excluded. `sourceRevision` fingerprints projected content, so excluded data
cannot perturb consumer identity.

Lifecycle refresh is deliberately a post-commit observer. Delivery artifacts are
refreshed only after their files exist; Explorer public state is projected only
through durable confined handoffs; Refinement stays document-first. Equal source
revisions are quiet. Compiler or publication failure cannot roll back the source
mutation that already succeeded.

Finally, the complete command surface was exercised by the unchanged external
probe against a fresh isolated home. Fixed fixture identities exist only behind
strict test-mode guards. The probe proved capability discovery, isolated
preparation, exact Operational content, inspection, extension publication,
last-valid preservation, traversal/namespace refusal, and atomic consistency.

## Conscious Exclusions

- No Tactical or Strategic interpretation is implemented by Mirror Core.
- No projection write-back, implicit repair, semantic synthesis, model call, or
  network dependency enters compilation or publication.
- No caller-supplied production root and no extension-selected namespace.
- No TypeScript implementation while CV22 remains paused; Python is the sole
  product authority for this contract.
- No production schema migration is required.
- The release does not authorize Nautilus projection work until its consumer-owned
  installed-runtime return record opens the gate.

## What We Learned

Atomic replacement alone is not a concurrency model. A trustworthy read-model
contract needs a clear linearization point, fresh state under exclusion, immutable
identity evidence, and an explicit posture for the narrow interval where one file
has moved and another has not.

Consumer-owned acceptance also sharpened the product boundary. By keeping the
probe immutable and external, Mirror could choose its architecture freely while
remaining unable to weaken the observable contract to fit its implementation.

## Next Horizon

With the installed-runtime return accepted, local consumers can build against the
Operational projection and extensions can publish their own versioned readings.
Tactical and Strategic meaning remains consumer/extension work. CV22 may later
port the observable command contract when its paused TypeScript migration resumes,
but no dual-authority obligation is created by this release.
