# v0.38.1 — The Refusal Names the Way Out

**Date:** 2026-10-30

## Highlights

- **A package with no home configured says where it looks and what to run**
  ([CR185](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr185-a-package-with-no-home-configured-does-not-say-where-it-looks.md)).
  The error names the homes it finds under `~/.mirror-minds`, the `mirror init <name>`
  that selects one, and the file that command writes. `mirror init <name>` now adopts a
  home that already exists, changing nothing in it, so moving from a clone to the
  package is one command. The bare `mirror` names the home too.
- **A missing OpenRouter key stops the command before it touches anything**
  ([CR187](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr187-a-missing-openrouter-key-crashes-three-commands-with-a-stack-trace-that-names-no-file.md)).
  The six commands that cannot work without it (`consult`, `journal`, `week plan`,
  `descriptor generate`, `consolidate scan`, and `shadow scan`) refuse in one line that
  says what was not done and where the key goes, and exit 2. `journal` says the entry
  was not saved, instead of crashing after it had copied the database into a snapshot.
  A key that OpenRouter refuses is one line too. `runtime status`, `runtime diagnose`,
  and a degraded search say when the key is missing.
- **A `stable` clone ahead only by `main`'s commits is told that `stable` is behind it**
  ([CR186](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr186-runtime-update-reads-main-s-commits-as-local-work.md)).
  The ways out are `runtime channel main` or the next release, in the words a package
  install already used. It is no longer told to push commits the remote already has, or
  to reset its code below a database that may be newer than `stable`'s. Real local work
  keeps the push-or-reset refusal.
- No migration, and no model or prompt change.

## Where We Started

v0.33.3 fixed installs under a non-ASCII path, which Leandro Garcia reproduced on PR #42.
On 2026-10-17 he came back with two bumps he met while following the update
instructions:

- Moving to the package, `runtime update` stopped with "Mirror home is not configured"
  and did not say where the package looks.
- On a clone, the release notes' manual step, `git pull --ff-only`, pulled `main` past
  the release. The next `runtime update` refused with `local commits present` and
  "push or reset", for commits that were not his.

The answer came on 2026-10-29, twelve days late. The v0.33.3 notes were corrected to
`git fetch origin` and `git merge --ff-only origin/stable`. CR185's review turned up a
third refusal of the same kind: with no `OPENROUTER_API_KEY`, `consult`, `journal`, and
`week plan` crashed with a stack trace that named no file, and `journal` lost the entry.

## What Changed

**A home the error can name (CR185).** One module now owns the homes root,
`~/.mirror-minds`, and decides what counts as a home there: a directory with a non-empty
`identity/` or a `memory*.db` file. The not-configured error is one line everywhere it
appears. It ends with the command that finishes the job:

```text
Mirror home is not configured. To use the home at <root>/<name>, run: mirror init <name> (it writes MIRROR_USER=<name> to <config>).
```

There are forms for several homes, for a home whose name `init` would refuse, and for
none. `init <name>` on an existing home copies nothing and changes nothing in it. It
writes `MIRROR_USER` to an owner-only config file when no home is selected, and prints
only what is left to do: the key, `mirror seed` when there is no database, and the
runtime wiring. Selecting the only home automatically was considered and refused. A
silent fallback once caused the wrong-session export incident, so one explicit command,
whose effect is kept in a file, is the honest minimum.

**A key checked before anything is touched (CR187).** The key used to be read at the
first model call, so a failing command could already have done work. A keyless
`journal` copied the whole database into its pre-write snapshot, then crashed. Now the
six commands that cannot work without the key check it before the database opens. Any
other command that meets a missing key is answered by the front door's handler: one
line, no stack trace. All the sentences come from one place and name the file the
install reads its configuration from. When that file does not exist yet, the line says
to create it readable only by its owner. A key that OpenRouter refuses (HTTP 401 or 403)
gets its own line, whether a chat call or an embedding call met it. `consolidate apply`
is not checked up front, because only a merge proposal embeds.

**The channel behind the clone (CR186).** The plan stage of `runtime update` counted
every commit in `origin/stable..HEAD` as the person's own. Releases only fast-forward
`stable` to `main`, so one more local count tells the two cases apart. When every commit
past `stable` is already on `origin/main`, the clone's channel is behind it. The update
then refuses the way the package lane refuses a channel behind the installed version,
and in its words: "A downgrade is refused: migrations do not run backwards.", then
`runtime channel main`, or staying until the next release. The captured Change Request
also offered a reset to `origin/stable`; it was dropped. `main`'s code can migrate the
database when it opens it, and `stable`'s core refuses a database newer than itself. One
function now reads where a clone stands, for both the update plan and the welcome card,
which had counted two different ways. A count that cannot run reads as local work, so
real work is never mistaken for published work.

**Reviewed before code, validated by hand.** Each plan was reviewed through persona
lenses before any code was written: five for CR185, four each for CR186 and CR187. The
Navigator validated each change on a natural route: CR185 and CR187 as a package user,
the lane Leandro was on, and CR186 in a scratch clone ahead of `stable`. CR186's reviews
turned its plan around. It had proposed reporting the clone as up to date, until the
engineer found the package lane already refusing the same state.

## Upgrading

```bash
mirror runtime update          # or: npm install -g mirror-mind@latest
```

No migration, and nothing to configure. Moving from a clone to the package with a home
that already exists: `mirror init <your-name>` now selects it without changing anything
in it, and says what is left, such as the key. No skill, plugin, or extension changed in
this release, so a reinstall line the updater prints for Codex, Antigravity, or Grok
Build only moves the version number.

## Conscious Exclusions

- Transport failures other than a refused key (a timeout, an outage, a rate limit, a
  server error) still crash the commands that call a model with a stack trace, and
  `journal` still loses the entry
  ([CR188](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr188-a-provider-outage-crashes-the-commands-that-call-a-model-with-a-stack-trace.md)).
- Extraction at session end with no key is unchanged, and a configuration error still
  counts as an attempt, which can quarantine a conversation
  ([CR178](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr178-a-configuration-error-counts-as-an-extraction-attempt-and-nothing-releases-a-quarantine.md)).
- With a wrong key, `descriptor generate` still prints "skipped (empty response)" for each
  persona. That line is golden-graded.
- `runtime update --check` still reports `local_ahead` for a clone ahead of `stable` by
  `main`'s commits, where a package reports `channel_behind`.
- A `main`-channel clone ahead by commits on another pushed branch keeps the
  push-or-reset refusal.

## What We Learned

A validation route is code too, and it has to be run before it is handed over. CR186's
route, run first by the agent, never reached the plan: a `node_modules` symlink made the
scratch tree dirty, because `.gitignore`'s `node_modules/` matches only a directory.
CR187's first route could not prove that no snapshot was taken, because `ls -l` shows
minutes. Both were caught before the Navigator ran them.

CI runs the suite under `MEMORY_ENV=test`. CR185's first push failed a test that had
assumed `memory.db`. The suite is now run that way before every push.

The same state deserves the same words. CR186's answer was already written, in the
package lane's refusal of a channel behind the installed version.
