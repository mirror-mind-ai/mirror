# v0.44.0 — A Persona the Host Can Create and Delete

**Date:** 2026-11-09

## Highlights

- **`createPersona`** writes a new persona under an id no persona holds and answers it as
  `readPersona` reads it ([CR207](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr207-let-the-host-create-and-delete-a-persona.md)).
- **`previewPersonaDeletion` and `deletePersona`** follow the Journey deletion: the act takes
  back the preview's digest and refuses with `persona_changed` when the home moved, behind a
  named backup it verifies first.
- **History stays, machinery goes.** Conversations, memories and runtime sessions keep the
  persona's id; its descriptor, identity integrations and extension bindings are deleted; a
  Journey's `default_persona` and the global sticky default naming it are cleared.
- No schema change, no migration. `DESKTOP_API_VERSION` stays 1.

## Where We Started

v0.42.0 gave a host `listPersonas`, `readPersona` and `updatePersona`, and left creating and
deleting out on purpose. Nautilus for Mirror lists every persona in its sidebar and asked for
the two acts that remain. A host could do either only by writing the `identity` table itself,
and a persona's id is read, without a foreign key, in eight places a careless deletion would
leave pointing at nothing.

## What Changed

**Create.** `createPersona(dbPath, { persona, name, prompt, description?, routingKeywords? })`.
The id follows the identity layer's grammar for a new key, a kebab slug of up to 80 characters,
so what the terminal can create a host can too; `invalid_persona_id` and `persona_exists` refuse
the rest. The row gets its own id and version `1.0.0`; its metadata is what the seed writes for a
persona file, without the fields not given. The default model and the inheritance are not taken.
CR203's router reads a persona's description first, so no descriptor is generated: the persona
is routable from the next turn.

**Preview.** `previewPersonaDeletion(dbPath, { persona })` answers the heirs, what stays
(`kept`), what goes (`deleted`), what is cleared (`cleared`) and a SHA-256 digest of all of it
with the persona's `updated_at`. It reads only.

**Delete.** `deletePersona(dbPath, { persona, expectedDigest })` re-reads the preview inside one
immediate transaction, refuses a different digest, refuses a persona others inherit from with
`persona_has_heirs` naming them, writes `backups/pre-persona-deletion-<id>-<UTC>-<random>.db`
(0600), checks that it reads as the same preview, and only then deletes. It answers the preview
it acted on and the backup's path, SHA-256 and size. A failure after the backup removes it.

**A closed inventory.** `PERSONA_DELETION_INVENTORY` names a decision for every schema column
that can hold a persona's id; a test reads the schema and fails on a column without one.

## Conscious Exclusions

- **No terminal command** to create or delete a persona; the calls are the host's.
- **No detaching of heirs.** No home seen holds a persona that inherits from another persona;
  the refusal guards that case until one exists.
- **`ext_*` tables are not searched**: no known extension column holds a persona's id. The
  bindings in `_ext_bindings` are deleted.
- **No undo.** The named backup is the way back, as for a Journey.

## Upgrading

```bash
mirror runtime update
```

Nothing to configure. A host that embeds the Core moves its pin to 0.44.0.
