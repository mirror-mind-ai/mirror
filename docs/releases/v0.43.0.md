# v0.43.0 — A Persona Edit That Reaches the Open Conversation

**Date:** 2026-11-08

## Highlights

- **An edited prompt reaches the conversation where the persona already spoke**
  ([CR206](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr206-deliver-a-persona-again-when-its-prompt-changed.md)).
  The next turn routed to that persona delivers its prompt again, under
  `=== persona/<id> (revised: replaces the earlier persona/<id> in this conversation) ===`,
  once.
- **Only the prompt counts.** The fingerprint is taken from the identity row's content, not
  from `updated_at`: renaming a persona or changing its description delivers nothing.
- **Upgrading delivers nothing again.** A session written by an earlier Core is read as
  delivered, and adopts the current fingerprint on its next turn.
- No schema change, no migration. `DESKTOP_API_VERSION` stays 1.

## Where We Started

v0.42.0 let a host edit a persona's prompt, but a delta delivered a persona's prompt once per
session and remembered only its id. An edit made while a conversation was open never reached
it: every later turn with that persona answered from the old text in the transcript, until a
compaction forced a full load.

## What Changed

**A map, not a list.** `doorman_personas` in the session's metadata maps each delivered
persona id to the first 16 hex digits of the SHA-256 of its prompt. The prompt itself is never
kept there. A delta routed to a persona compares: not held, the ordinary section; same
fingerprint, nothing; another, the revised section and the new fingerprint.

**The full load records too.** `runFull` keeps the fingerprint of the persona it delivered, so
an edit made right after a full load, before any delta, is seen.

**A compaction starts over.** `forgetDoormanDelivery` empties the map; the next turn is full
and its persona a first delivery, never a revision.

**An earlier session is adopted.** Its list of ids reads as delivered with an unknown
fingerprint; the first turn routed to each persona delivers nothing and keeps the current
fingerprint. An edit made before that first turn is seen only at the next edit or compaction.
Going back to an earlier Core costs one repeated section per persona, nothing else.

## Conscious Exclusions

- **The old text stays in the transcript.** The revised header says which one is in force;
  a compaction removes the old one.
- **An edited prompt keeps its generated descriptor**, as `mirror identity set` does;
  `mirror descriptor generate` refreshes it.
- **The field falsifier is not run yet.** Its four cases need a host on a real Pi session; they
  run when Nautilus for Mirror embeds this release.

## Upgrading

```bash
mirror runtime update
```

Nothing to configure. A host that embeds the Core moves its pin to 0.43.0.
