# v0.44.1 — A Help Flag That Only Helps, and a Journey the Host Keeps

**Date:** 2026-11-17

## Highlights

- **A host's Conversation keeps the journey the host gave it**
  ([CR216](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr216-a-mirror-load-moves-a-host-conversation-to-another-journey.md),
  PR #79). A full Mirror load wrote its resolved journey over whatever Conversation the guessed
  session pointed at, and the guess could land on a host's session. Nautilus for Mirror met it on
  2026-09-26: a Conversation moved to another journey and every later delivery was refused.
  `ensureConversation` now marks the journey as the host's; the guess skips such sessions; the
  load never moves that journey and never writes a null over a persona or journey it did not
  resolve.
- **`--help` after a command only answers**
  ([CR215](../project/refinement/rs009-cv22-front-door-routing-correctness/cr215-a-help-flag-after-a-subcommand-runs-the-subcommand.md)).
  `-h` or `--help` anywhere among a command's arguments prints that command's usage, exit 0,
  and runs nothing. Before, `tasks delete <id> --help` deleted the task, `tasks add --help`
  created one titled `--help`, and `mirror log --help` recorded `--help` as a reply.
- **`runtime <subcommand> --help` and `mirror --version`**
  (PR #60, Rodrigo Immaginario, issue #58): `runtime update --help` used to perform an update.
  CR215 generalizes the fix to every family.
- **The operating instructions** bound a task's size
  ([CR211](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr211-the-operating-instructions-bound-nothing-about-a-tasks-size.md))
  and describe persona routing as the runtime does it
  ([CR213](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr213-agents-md-describes-the-persona-routing-cr203-replaced.md)).
- No schema change, no migration. `DESKTOP_API_VERSION` stays 1.

## Where We Started

Two ways of being surprised by a command that did what it was never asked. A person or an agent
probing an unfamiliar command with `--help` could change data, spend money or move the operating
mode, because most subcommands read the options they know and drop the rest. And a host that
embeds the Core could lose a Conversation's journey to a terminal's Mirror load, with no event
and no receipt, found only as rejected deliveries.

## What Changed

**CR216.** `ensureConversation` merges `journey_authority: "host"` into the Conversation's
metadata, reading it inside the write so the keys the close tail and learning keep survive; a
Conversation ensured before this gets the mark on its next ensure. `guessRuntimeSessionId`
leaves out a session whose Conversation carries the mark, and malformed metadata counts as
unmarked. `bindConversationContext` sets the persona only when the load resolved one, and the
journey only when it resolved one and the Conversation is not a host's. A named session still
resolves, and `rebindConversationJourney` stays the one way to move a host's Conversation. The
guess is shared, so Builder, Soul and Explorer loads and the prompt logger gain the same rule.

**CR215.** One rule in routing, after the retired match and before any family, answers the help
flag through the usage engine, which answers before anything is opened, read from stdin or
spawned. The answer is the subcommand's own usage line where there is one, else the family's.
The prompt that is exactly `-h` or `--help` still reaches the doorman, on every runtime's hook
path, and `conversations imported`, `conversations skill-turns` and `ext` keep their own help.
`mirror log` refuses a summary that looks like an option, as `journey update` has since CR073.
`build`'s usage lines are generated from the argument specs its parser enforces.

**CR211 and CR213.** `AGENTS.md`, which every runtime reads, gains a scope rule and says that
Mirror chooses each turn's persona, which the Core has done since v0.41.0. `mirror detect-persona`
is described as the keyword match it is, not the turn's router.

## Conscious Exclusions

- **No audited record of a journey change** (CR094's third option): with a host's journey
  protected, the moves that remain are terminal Conversations following their own load.
- **`--` as an end-of-options marker**: no parser honors it.
- **Refusing unknown flags across families.**
- **The sticky defaults and which session a named load binds**
  ([CR209](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr209-a-journey-cannot-be-set-for-one-session.md)).

## Upgrading

```bash
mirror runtime update
```

One visible change: `build ... --help` exits 0 with the usage, where it used to exit 2 with
`unrecognized argument --help`; so does `init --help`. A host that embeds the Core moves its pin
to 0.44.1.
