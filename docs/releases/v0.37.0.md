# v0.37.0 — The Mirror Stays in the Conversation

**Date:** 2026-10-25

## Highlights

- One doorman decides what Mirror puts before the model on each turn, on Pi, Claude
  Code, Codex, and Antigravity: the full context on the turn Mirror Mode starts, then
  the persona each question calls for and the memories relevant to it, and nothing
  when Mirror Mode is off.
- Pi reaches L4. A Pi conversation keeps the mirror's voice after the first answer,
  moves to another persona when the topic moves, and signs every answer. Measured live
  on Pi 1.4.0.
- An explicit Mirror turn loads once. The `mm-mirror` skill no longer loads a second
  time when the runtime already delivered the context.
- One signature rule, `◇ persona-name`, in `AGENTS.md`, the skill, and the core's
  banner; `✦ Persona:` is gone.
- Measured live before it was written down: Claude Code 2.1.310 and Codex 0.164.0
  (16 of 16 checks), Pi 1.4.0 (three walks), agy 1.4.7.
- CV21 closes: the runtime interface contract holds one parity matrix, each row
  sourced to a measurement, and a test holds README, Getting Started, REFERENCE, and
  the architecture to it.
- Migration 018 drops `runtime_sessions.hook_injected`; Mirror backs up and migrates
  each home on its own.
- Codex, Antigravity, and Grok Build keep their own copy of the plugin: bring it level
  after updating; `mirror runtime diagnose` names the command.

## Where We Started

Mirror Mode is the product. Mirror builds a folder from the database (the identity
layers, a persona routed from the question, the journey, the shadow patterns, and the
memories and attachments relevant to it) and the model answers as the mirror with that
folder open. What decides the experience is whether the folder reaches the model, and
when.

Until this release, three runtimes gave three answers. The Claude-family inject hook
delivered the folder on an explicit Mirror turn and once on the next ordinary turn,
then never again. Antigravity's hook delivered the whole folder on every turn, but agy
1.4.2's hooks carried no prompt, so nothing could be routed from the question. Pi had
no doorman at all. Measured on Pi 1.4.0 on 2026-10-24
([CR165](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr165-pi-puts-no-mirror-context-before-the-model.md)),
the model loaded the folder once, through the skill, and answered every follow-up from
that one load: no reload, no new persona when the topic changed, no signature after the
first reply. And wherever a doorman did exist, the skill's own rule, "never answer
without loading first", made the explicit turn load twice.

CV21.DS11, writing the parity matrix, made the line explicit: at L4 the runtime puts
Mirror's context before the model; at L3 the model loads it itself. By that line Pi, the
harness Getting Started recommends, was L3.

## What Changed

### One doorman

[CV9.DS8](../project/roadmap/cv9-mirror-1-0/cv9-ds8-one-doorman-mirror-s-context-before-the-model-on-every-runtime/index.md)
built one decision in the core, `ts/src/mirror/doorman.ts`. Given a turn's prompt and
the session's state it answers one of three things:

- **the full folder**, when the prompt opens with the explicit Mirror form in any
  runtime's spelling (`/mm-mirror …`, `/mm:mirror …`, `$mm-mirror …`, the plugin
  spellings); the session is marked in Mirror Mode;
- **a delta**, on an ordinary turn while Mirror Mode is on: the section of a persona the
  question newly calls for, which becomes the session's; up to five memories scoring at
  least 0.4 on the semantic score that the conversation has not been given yet; and the
  attachments scoring above 0.4. The identity layers are already in the transcript and
  are not repeated;
- **nothing**, when Mirror Mode is off, or on a skill command other than the Mirror
  form, with no model call.

Every block opens with one line the model reads, on every turn Mirror Mode is on: it
says what was delivered and carries the persona and the signature rule across the
conversation. The `mm-mirror` skill trusts that line and loads only when the runtime
did not deliver the context for this turn, so an explicit turn loads once.

"Mirror Mode on" takes two facts: the session's Mirror flag, and its operating mode
still being Mirror Mode. Switching to Builder, Explorer, or Soul Mode ends the deltas,
and `/mm-new` ends Mirror Mode; on Pi it now does, because the session is named. When
the model answers a personal question as the mirror on its own, its load names the
session from the runtime's environment (`MIRROR_SESSION_ID`, `CLAUDE_CODE_SESSION_ID`,
`CODEX_SESSION_ID`), so the doorman takes over from the next turn. The doorman never
guesses a session.

Three choices shaped the policy, recorded in the
[decisions log](../project/decisions.md#one-doorman-puts-mirrors-context-before-the-model-on-every-runtime):
memories are refreshed on every turn in Mirror Mode, at one embedding call each, counted
in the ledger; there is one signature, `◇ persona-name`; and the work was a Delivery
Story under CV9, measured live on every runtime it touched.

### Each runtime through it

- **Claude Code and Codex.** The inject hook hands each prompt to the doorman and
  returns its block as the hook's context. Measured live on Claude Code 2.1.310 and
  Codex 0.164.0: the explicit turn loads once, a follow-up in another domain moves to
  that persona and signs it, a Builder switch ends the deltas, and a personal question
  the model answers on its own is followed by doorman turns. 16 of 16.
- **Pi.** The extension's `before_agent_start` hands each turn to the doorman and
  carries its block into the run; after Pi compacts a session, the next turn gets the
  full folder again. Measured live on Pi 1.4.0 in three walks, and Pi's row in the
  parity matrix moves to L4.
- **Antigravity.** agy 1.4.7 carries the prompt in every hook payload
  (`lastUserInput`), so `PreInvocation` hands each turn to the doorman and answers its
  block as a persistent step; a conversation's first turn gets the full folder.
  Measured live on agy 1.4.7, at 0.23–1.02 s a turn against agy's 15 s budget. Before
  agy 1.4.7, the earlier injection stays as it was.
- **Grok Build** stays at L3. Grok discards the context a hook offers, so Mirror Mode
  there still comes from the skill.

### What a turn costs

A turn in Mirror Mode writes one `embedding` row in `llm_calls`; the explicit turn
costs what `mirror load --query` costs; a turn outside Mirror Mode makes no model call.
Measured with the `mirror mirror doorman` command on a copy of a real home: a delta in
about 1 s, 142–154 bytes when no memory passes the threshold and up to 8.5 KB when some
do; the full folder, 33 KB, in 1.33 s; a turn outside Mirror Mode in 0.21 s. No price in
dollars was measured; the ledger counts the calls.

## Upgrading

```bash
mirror runtime update          # or: npm install -g mirror-mind@latest
```

Migration 018 drops one column nothing reads any more, `runtime_sessions.hook_injected`.
Mirror applies it on its own: the first time it opens a home after the update, it backs
the database up and migrates it.

Then, for each runtime you use:

- **Pi:** restart every Pi session. A session keeps the extension it loaded.
- **Claude Code:** start a new session. The plugin is a link into the package, so there
  is nothing to re-wire.
- **Codex, Antigravity, Grok Build:** each keeps its own copy of the plugin, which an
  update leaves behind, and the `mm-mirror` skill in it changed. Run
  `mirror runtime diagnose`: it names the one command that brings each copy level
  (`codex plugin add mirror-mind@mirror-mind` for Codex, `agy plugin install
  "<pkg>/plugins/mirror-mind"` for Antigravity, an uninstall and an install for Grok
  Build). Then start a new session.
- **Antigravity before 1.4.7** keeps the earlier injection; update agy to get the
  doorman.

## Conscious Exclusions

- **Grok Build stays at L3** (CR143): it discards hook context, so there is nothing for
  a doorman to deliver through.
- **The model's own commands on Antigravity cannot name the session yet**
  ([CR169](../project/refinement/rs010-cv22-oracle-and-port-hygiene/cr169-on-agy-the-model-s-own-mirror-commands-cannot-name-the-session.md)):
  a Mirror load the model starts by itself there is not followed by doorman turns, and a
  Builder switch the model runs guesses the session. Antigravity's compaction has no
  hook to bring the folder back (CR173), and an execution agy starts with no new user
  input would hand the doorman the previous prompt (CR170, unmeasured).
- **A prompt that is exactly a doorman flag**, such as `--forget`, is read as the flag
  (CR171).
- **What the folder contains is unchanged.** The doorman decides when Mirror's context
  reaches the model and which part of it; how personas are scored and how memories are
  ranked stay as they were.
- **No price was measured.** The ledger counts every call; a turn's cost in dollars is
  still decision 1's estimate.
- **A checkout plus the installed plugin runs Claude Code's inject hook twice**, paying
  two embeddings a turn: a contributor-only condition, named in CV9.DS8.US4 and not yet
  a Change Request.

## What We Learned

- **A level is a measurement.** Pi was claimed at L4 until the parity matrix asked for
  the record behind every level; asking is what showed the gap this release closes.
- **Probe before building.** The plan for Antigravity was to read the prompt from the
  transcript. The probe meant to time that read found agy 1.4.7 carrying the prompt in
  every payload, and the transcript reader was never written.
- **Say what "on" means.** "Mirror Mode on" needed two facts, the session's flag and its
  operating mode. A review found it before a live walk did, which would have been a
  Builder answer in the mirror's voice.
- **Threshold the score that measures relevance.** A threshold on the hybrid ranking
  score would have been a recency gate; the memory threshold reads the semantic score,
  the one attachments already used.
